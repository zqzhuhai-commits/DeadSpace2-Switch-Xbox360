## 重建最终翻译资源

需要 Python 3，在仓库根目录执行：

```sh
python translation-final/tools/rebuild_final.py
```

Windows 可以将 `python` 换成 `py -3`。该脚本覆盖 `translation-final/translation/zh_CN_final.lh2` 并更新同工程 `validation_report.json`。只编辑 JSON 的 `translation` 字段，保留索引、ID、源文、按钮、变量及换行控制符。

该脚本只重建原最终翻译工程的 LH2，**不会更新 v0.4 的字体、TOC、嵌入资源或 EXE**。v0.4 术语调整记录见 `current/v0.4/Translation/terminology_changes.json`。修改译稿后，要重新生成匹配的资源及字体并编译；现有 build.py 只编译已经封装好的资源，不负责上述完整流水线。历史包内已有步骤和脚本按原样保留，不代表缺失流程已被补齐。

## 从源码编译 v0.4

安装 Python 3 与 Zig，在仓库根目录执行：

```sh
cd current/v0.4/Source
python build.py
```

也可 `python build.py /path/to/zig` 指定 Zig。输出 `DS2_Tool_v04.exe`，目标为 Windows x86_64。编译会生成 `payload_v04.S`。本次归档未重新编译或运行 Windows GUI；随包 EXE 原样保留。

## 双盘合并和安装

1. 解压 v0.4，阅读完整使用说明，保留可恢复的原版。
2. 运行工具，选择 Disc 1 自己的完整 `bigfile0.viv`；不要选择 ZIP、LH2 或单独提取资源。
3. 选择尚不存在的输出路径，例如 `bigfile0_zh.viv`。预留至少一整份 VIV 加约 5 MB 空间。
4. 如勾选“自动备份并安装”，输入与输出放在同一磁盘。
5. 点击“开始合并”，等待复制、追加、索引更新和校验结束。
6. 自动安装成功后，原文件改为 `bigfile0.viv.original.日期_时间_序号.bak`，生成文件使用原 `bigfile0.viv` 名称。
7. 对 Disc 2 自己的完整文件重复操作，不能用 Disc 1 整包覆盖 Disc 2。
8. 将相应文件放回各自数据目录，语言设为 English。

取消自动安装时，只生成输出文件；自行确认备份后再替换。版本不匹配时停止并恢复匹配原版，具体错误处理见 v0.4 使用说明。

## 恢复

关闭游戏，将当前修改文件另行改名，再把同盘对应 `.original.日期_时间_序号.bak` 改回 `bigfile0.viv`。保留两盘各自备份，不要交叉使用。

## 验收与未完成项

现有包报告记录：LH2 索引、ID、控制标记和二进制往返检查通过；四套字体覆盖目标字符；合并核心通过构造 BIGH 文件的多种成功与拒绝/回滚检查。该结果不等同于完整 VIV、Windows GUI 或主机运行验证。

仍需在匹配完整 VIV 和设备上验证：

- Disc 1、Disc 2 分别完整合并、启动与切盘。
- 菜单“新游戏”无测试字样，物品栏、商店、日志、剧情字幕显示中文。
- 字库纹理兼容、缺字、间距、长文本溢出和崩溃情况。
- 全流程文本覆盖与翻译逐句校对。

出现异常时记录盘号、游戏版本、所用工具版本、原始文件 SHA-256、错误提示及日志，恢复备份后定位问题。未经这些验收，不标记为最终实机交付版。
